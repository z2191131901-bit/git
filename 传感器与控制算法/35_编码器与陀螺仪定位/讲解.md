# 35 编码器＋陀螺仪：先把小车在平面上走过的路算出来

配套代码：[编码器与陀螺仪定位.c](编码器与陀螺仪定位.c)。建议先读 [编码器测速](../21_编码器测速/讲解.md) 和 [差速里程计](../22_差速里程计/讲解.md)。

## 1. 两个传感器分别回答什么问题

编码器回答“轮子滚了多远”，陀螺仪回答“这段时间车身转了多少角度”。
把距离沿着车身前进方向投影到世界坐标系，就能不断更新位置。

严格说，本篇是编码器辅助的平面航位推算，还没有加速度计驱动的完整惯性递推。
日常小车项目常把它也叫“惯导定位”，但理解这个区别，后面选算法才不会混淆。

只有这两个传感器时，没有绝对位置来源。即使每一步都正常计算，长期误差也会累积。
代码能从指定初始位姿往后推算，不能自己知道启动时在地图的哪个位置。

## 2. 输入输出和单位

| 变量 | 意义 | 单位 |
| --- | --- | --- |
| left_m、right_m | 本次时间区间内左右轮的有符号行程 | m |
| gyro_z | 同一区间内机体 Z 轴平均角速度 | rad/s |
| bias | 预先标定的陀螺仪零偏 | rad/s |
| dt | 本区间持续时间 | s |
| state.x、state.y | 局部世界坐标中的位置 | m |
| state.yaw | 从世界 X 轴转向车头的角度 | rad |

机体 X 向前、Y 向左、Z 向上；左转为正角度。
世界坐标原点和初始朝向由你指定，例如开机位置是 (0,0)，开机车头方向是世界 X。
这不代表世界 X 就是地理正东。

左右编码器的机械安装可能使计数符号相反，要在驱动层统一成“车向前，两个轮子的行程都为正”。
倒车不能对计数取绝对值，否则会把后退算成前进。

## 3. 原始计数先变成距离

如果轮半径为 r，每轮一圈最终得到 N 个计数：

~~~text
轮子距离 = 本周期计数增量 × 2πr / N
~~~

这里 N 必须包含正交编码器倍频和减速比的影响。
如果编码器装在电机轴上，不要直接把电机一圈当成轮子一圈。
本例接收已经转换好的距离，不处理定时器回绕，回绕应在计数驱动层解决。

左右轮数据要覆盖相同起止时间，陀螺仪也要对应这个区间。
低频读取轮子后，不能把最后一个陀螺仪瞬时值当成整个长区间的平均转速。
更可靠的做法是累计区间内的陀螺仪角度增量。

## 4. odometry_step 按执行顺序讲解

第一步检查指针、有限数和 dt。NaN 是无效浮点值，继续使用会使后续结果全变成 NaN。
函数在局部变量 next 上计算，成功才写回，失败时旧位姿仍可用。

第二步计算小车中心的行程：

~~~text
ds = (left_m + right_m) / 2
~~~

这是两轮差速车无侧滑模型下的中心弧长。
原地转向时，两轮一正一负且大小相等，因此 ds=0。

第三步先扣零偏，再对角速度积分：

~~~text
angle = (gyro_z - bias) × dt
~~~

例如静止时读数一直是 0.02 rad/s，那么 bias 应接近 0.02。
这个参数不是滤波强度，也不是转向比例，不能凭感觉随便调。

第四步计算这一段圆弧的弦长和中间朝向：

~~~text
half = angle / 2
sinc = sin(half) / half
chord = ds × sinc
middle_yaw = old_yaw + half
~~~

为什么不直接用 ds？转弯时 ds 是圆弧长度，位移是两端点之间的弦长。
当 angle 很小时二者接近；当 angle 较大时，区别不能忽略。

half=0 时直接除法会得到 0/0，所以代码用极限附近的展开式：

~~~text
sinc ≈ 1 - half² / 6
~~~

第五步投影到世界 X/Y：

~~~text
new_x = old_x + chord × cos(middle_yaw)
new_y = old_y + chord × sin(middle_yaw)
new_yaw = wrap(old_yaw + angle)
~~~

wrap 用 atan2(sin(a),cos(a)) 把角度保持在主值范围，避免不断转圈后角度无限变大。

这套圆弧公式对本区间内恒定线速度和角速度成立。
如果区间内运动变化很快，缩短采样周期，不要认为一个大时间步也能精确重建轨迹。

## 5. 手算一次 90° 转弯

设初始 (x,y,yaw)=(0,0,0)，线速度 1 m/s，角速度 1 rad/s，持续 π/2 秒。

~~~text
ds = π/2
angle = π/2
half = π/4
chord = (π/2) × sin(π/4)/(π/4) = √2
dx = √2 × cos(π/4) = 1
dy = √2 × sin(π/4) = 1
~~~

所以终点为 (1,1)，车头朝向 π/2。这正是半径 1 m 的四分之一圆。
main 把这段运动分成 100 次调用，用解析终点检查结果。

## 6. 为什么没有用轮距算转角

第22篇用 (右轮行程−左轮行程)/轮距算转角。
本篇换成陀螺仪转角，因此没有轮距参数。

这并不代表陀螺仪在任何时候都更准。轮子打滑会影响编码器，陀螺仪会有零偏、温漂。
若要融合两种转角，需要各自的误差模型，不能简单宣称固定各占一半最优。
本篇先把最容易读懂、容易接硬件的一条路径写清楚。

## 7. 零偏误差演示

小车实际直行 10 秒，速度 1 m/s，但陀螺仪残留 0.02 rad/s 零偏：

~~~text
错误累计转角 = 0.2 rad
错误侧向位置 = [1 - cos(0.2)] / 0.02 ≈ 0.996671 m
~~~

这是近 1 m 的侧向误差，不是只错了一个角度。
代码同时运行扣零偏和不扣零偏两个分支，帮助你看到方向误差如何变成位置误差。

开机静止平均可以估计零偏，参考第05篇；温度变化后仍可能需要重新估计。
不能在正在转向时把角速度均值当成零偏减掉。
