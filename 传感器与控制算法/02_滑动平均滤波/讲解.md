# 滑动平均：从“算四个数的平均值”开始

[打开配套代码](滑动平均滤波.c) · [返回学习入口](../新手从这里开始.md)

这篇只需要你会加法和除法。读完应该能回答：为什么保存最近几次读数？第5个数来了以后丢掉哪个？这些动作怎样写成C函数？

## 1. 先看一个你可能遇到的问题

假设温度计每次读取都得到一个数，连续读到：

~~~text
20、22、19、21
~~~

显示屏直接显示每次读数，会在20、22、19、21之间变化。我们希望显示平稳一点，可以把这四个数平均：

~~~text
(20 + 22 + 19 + 21) / 4 = 20.5
~~~

这叫平均滤波。“滤波”在这里就是对读数做处理，减轻某些变化。
它不能凭空找出真实温度；遇到真实的快速变化，平均也会让显示反应变慢。

“滑动”的意思是只保留最近几个数。新的来了，最旧的离开。
本例保留最近4个数，这4个位置叫“窗口”。窗口不是电脑上的界面窗口。

## 2. 算法接收什么，返回什么

| 内容 | 本例是什么 |
| --- | --- |
| 每次输入 | 一个刚读到的数，例如18 |
| 每次输出 | 最近最多4个有效读数的平均值 |
| 跨调用保存的数据 | 历史读数、总和、有效数量、下次写入位置 |

如果输入是摄氏度，输出仍是摄氏度。函数不知道你接了温度计还是加速度计。
“采样”就是读取一次；“采样周期”就是两次读取之间隔多久。
例如每0.01秒读一次，就是每秒100次，也叫100Hz。

## 3. 用配套代码里的数字，完整手算一遍

代码输入为10、12、14、16、18、20。它们刻意简单，方便检查结果。

| 第几次 | 新输入 | 最近的有效数据（从旧到新） | 总和 | 输出 |
| --- | --- | --- | --- | --- |
| 1 | 10 | 10 | 10 | 10/1=10 |
| 2 | 12 | 10、12 | 22 | 22/2=11 |
| 3 | 14 | 10、12、14 | 36 | 36/3=12 |
| 4 | 16 | 10、12、14、16 | 52 | 52/4=13 |
| 5 | 18 | 12、14、16、18 | 60 | 60/4=15 |
| 6 | 20 | 14、16、18、20 | 68 | 68/4=17 |

第一次只有一个有效数，所以除以1。
数组里另外三个位置虽然初始化为0，但它们还没有收到读数，不能计入平均。

第5次来了18，丢掉最旧的10：
旧总和52 − 旧值10 + 新值18 = 新总和60。
这样每次只做一次减法和一次加法，不需要重新加遍整个窗口。

## 4. 先认清代码中用来记忆的四个成员

~~~c
typedef struct
{
    float samples[4]; /* 四个历史数据位置。 */
    size_t next;      /* 下一个新数据写到哪里。 */
    size_t count;     /* 已经有多少个有效读数，最多4。 */
    double sum;       /* 有效读数的总和。 */
} MovingAverage;
~~~

这是帮助阅读的摘录；实际代码用WINDOW_SIZE表示4。
struct把几份相关数据装在一起；typedef给这组数据起名字MovingAverage。
size_t在这里保存非负数量与数组下标。float和double都是小数类型，double通常有更高精度。

`samples[0]` 是第一个位置，`samples[3]` 是第四个位置。C数组从0开始编号。
next和“当前有效数据个数”是两回事。窗口满后count保持4，next仍不断循环。

~~~c
MovingAverage filter = {0};
~~~

这行创建一份滤波器记忆并把成员置零。它应在采样循环外执行一次。
温度和电流是两个通道，需要各有一份记忆。

## 5. 一次函数调用该怎么读

配套代码的调用是：

~~~c
float output = 0;
int ok = moving_average_update(&filter, input[i], &output);
~~~

逐个看：

| 写法 | 这次的作用 |
| --- | --- |
| &filter | 把滤波器记忆的地址交给函数，函数可以更新它 |
| input[i] | 这一次的新读数 |
| &output | 告诉函数把平均值写到哪个变量 |
| ok | 1表示这次计算成功，0表示拒绝本次输入 |

地址可以理解为变量在内存里的位置。
函数里的state是指向滤波器的指针，`state->sum` 就是访问该滤波器的sum成员。
`*output = ...` 表示沿着结果地址，把算出的值写给调用者。
首次只要认出这些写法在这里的用途即可。

## 6. 跟着一个具体的“第5次调用”走进函数

第5次调用前：count=4、next=0、sum=52、samples[0]=10，新输入18。

**第一步：检查输入。** 地址不能为空，输入不能是NaN或无穷大。
NaN表示“不是一个有效数值”，例如某些非法运算的结果。
检查失败返回0，保留原状态和输出。

**第二步：减旧值。**

~~~c
state->sum -= state->samples[state->next];
~~~

`x -= y` 等价于`x = x - y`。所以sum从52变为42。
窗口未满时不减旧值，只增加count。

**第三步：覆盖旧位置，加上新值。**

~~~c
state->samples[state->next] = input;
state->sum += input;
~~~

samples[0]从10改为18，sum从42变为60。
物理数组此时是18、12、14、16；按时间排列则是12、14、16、18。
数组不用搬动，next会记录哪个位置最旧。

**第四步：移动写入位置。**

~~~c
state->next = (state->next + 1) % WINDOW_SIZE;
~~~

%表示取余。窗口4时，位置依次是0、1、2、3，再回到0。
这次next从0变为1，下次覆盖12。

**第五步：写出平均值。**

~~~c
*output = (float)(state->sum / (double)state->count);
~~~

本次60/4=15。括号里的类型转换让编译器明确用哪种小数类型计算和保存。

## 7. 在电脑上运行，应看到什么

先在PowerShell进入仓库根目录，再运行：

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\传感器与控制算法\验证全部示例.ps1 -示例 滑动平均滤波.c
~~~

需要已安装的gcc能从命令行找到。若提示找不到gcc，是编译环境尚未配置。
脚本自动编译、运行，不需要连接传感器。

主要输出：

~~~text
input=10.0 average=10.0
input=12.0 average=11.0
input=14.0 average=12.0
input=16.0 average=13.0
input=18.0 average=15.0
input=20.0 average=17.0
moving_average: PASS
~~~

main是程序入口。它把模拟数据逐个送入函数。
expected数组保存我们手算的答案；assert核对程序结果与答案。
assert失败会终止程序。不要定义NDEBUG关闭验证。

程序还故意输入一次NaN：应拒绝该输入，输出保持17。
随后输入22，得到(16+18+20+22)/4=19。

## 8. 改哪几个地方能帮助理解

先在纸上把输入改成4、8、12、16、20。
预期输出为4、6、8、10、14。修改代码input时，也要对应修改expected。
配套代码后面的NaN和22检查依赖原输入，需要一起重新手算，不能只改前一处。

再思考：窗口从4改为8会怎样？
保存的数据更多，通常更平滑，但响应真实变化也更慢。不要仅凭“更平滑”判断更准确。

如果想看慢响应，输入一串0后突然持续输入100，观察输出如何逐步达到100。
这类实验必须相应调整验证答案。

## 9. 常见卡点

| 现象 | 先检查 |
| --- | --- |
| 输出一直等于最新输入 | 是否每次调用前都重新初始化filter |
| 第一拍10却得到2.5 | 是否把未收到的三个样本也计入平均 |
| 第5拍结果不对 | 是否覆盖旧值之前忘了从sum中减掉它 |
| 两个传感器互相影响 | 是否共用了同一个filter |
| 改了输入后assert失败 | 是否仍在使用旧expected答案 |

原函数要求状态用{0}初始化且不被其他代码破坏，结果变量也不能放在滤波器内部。

## 10. 第一遍读懂后再看

窗口填满、等间隔采样时，这个平均滤波的延迟为(N−1)/2个采样周期。
N=4、周期0.01s，延迟为0.015s。
更新运算数量与窗口大小无关，叫O(1)；历史存储随N增长，叫O(N)。

这些术语用于描述开销，第一次读时可以跳过。
