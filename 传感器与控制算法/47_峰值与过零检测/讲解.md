# 47 峰值与过零检测

配套代码：[峰值与过零检测.c](峰值与过零检测.c)。本例采用标准 C99，无第三方依赖。

## 1. 两种检测分别做什么

峰值检测识别局部最高点；过零检测寻找信号从负变为非负的位置。
周期信号可以用相邻同方向过零时间估算频率。

本篇把两种简单检测放在一个程序中，但并不把“峰值数量”直接当频率。
复杂、带强噪声的振动分析需要更完整的预处理或频谱方法。

## 2. 三点严格峰值

保存older、previous，当前输入为x。
如果previous>older且previous>x，并且previous>=threshold，
就确认previous是一个峰值。

因为必须等到右边的x到来，确认延迟一个采样周期。
事件里的peak_value是previous，不是当前x。

本例采用严格大于，因此[0,1,1,0]这样的平顶不会被算作峰值。
main专门验证了这一限制；需要平顶中心定位应另行定义平台处理规则。

## 3. 只看上升过零

~~~text
previous < 0 且 x >= 0
~~~

这样每个普通正弦周期只出现一次对应事件。
如果同时统计上升和下降过零，却仍把间隔当整周期，频率会算成两倍。

等于零归入非负侧。
连续多个零不会重复触发，但信号在零附近来回抖动仍可能触发多次。

## 4. 为什么插值过零时间

真实过零可能位于两个采样点之间。
把这一小段近似为直线：

~~~text
fraction = -previous/(x-previous)
crossing = previous_time + fraction*(time-previous_time)
~~~

例如t=1.0时x=-0.2，t=1.1时x=0.3：
fraction=0.2/0.5=0.4，估计过零时刻为1.04 s。

这只是局部线性插值；采样率太低时，不能靠插值恢复丢掉的波形信息。

## 5. 从周期到频率

第一次过零只能记录时刻。
第二次开始：

~~~text
period=current_cross-last_cross
frequency=1/period
~~~

time单位为s，frequency单位为Hz。
frequency_valid表示这一拍是否真的有新频率，不能每次都把frequency字段当新测量。

Detector全零初始化；samples饱和保持在2，只表示历史点是否充足，不无限计数。
输入时间必须严格递增。

## 6. 噪声与偏置

峰值threshold可以忽略较小局部峰，但没有设置最小峰间距。
过零检测没有加滞回，噪声可能导致频率虚高；可结合第39篇思想设计迟滞过零。

大的直流偏置可能让波形永远不过零。
使用前应明确是否需要去均值、带通等处理。
过零频率适合近似单周期波形，不等于一般混合信号的主频。

## 7. 本例验证

用2 Hz正弦、100 Hz采样、持续2秒，期望4个峰和4次上升过零。
第一次过零没有周期，后面得到3个2 Hz频率估计。
还检查重复时间戳拒绝、平顶不算峰。
输入按普通有限工程量使用，不用于极端接近浮点范围上限的波形。
