# 40 按键消抖

配套代码：[按键消抖.c](按键消抖.c)。本例采用标准 C99，无第三方依赖。

## 1. 为什么按一次会出现多个边沿

机械触点接通和断开时，原始电平可能短时间反复变化。
直接检测每个电平变化，会把一次操作识别成多次。

本例定时采样，要求连续 N 次读到与稳定状态不同的值，才确认改变。
输入已经统一成1=按下、0=松开；低电平有效引脚要先取反。

## 2. 状态逐项解释

stable 保存已经确认的按键状态。
count 记录连续出现“相反状态”的次数。
required 是需要连续确认的次数，必须大于0，运行中保持不变。

Button b={0,0} 表示开机认为按键松开。
如果开机时已经按住，也会在连续 required 次采样后产生按下事件。

## 3. sample 的执行顺序

读到与 stable 相同的值，说明相反状态没有持续成立，把 count 清零。
读到相反值，count加一；不够 required 就继续等待。
达到 required 后，stable=raw，count归零，并且只返回一次边沿事件。

二值输入只有两个可能值，所以不需要再存候选状态。
不能把本实现直接套在三档开关上，因为“不同于stable”不再只对应一个值。

## 4. 返回值不是按键电平

| 返回值 | 意义 |
| --- | --- |
| 1 | 本次刚确认按下 |
| -1 | 本次刚确认松开 |
| 0 | 没有新的事件 |
| 2 | 参数错误 |

持续按住时，第一次确认后不再重复返回1。
要判断当前是否按住，读取 b.stable。
长按、双击和连发应在稳定状态/事件之上另外实现，本例没有包含。

## 5. 手算 required=3

从稳定松开开始：

~~~text
raw:   1  0  1  1  1
count: 1  0  1  2  0
事件:  无 无 无 无 按下
~~~

最后一次把stable置为1并清零计数。
按下后的raw=1属于原稳定状态，不会再次产生按下事件。

## 6. 消抖时间与采样周期

如果每5 ms采样一次，required=4，则确认延迟随边沿相位约为15~20 ms。
“四个样本”之间只有三个间隔，所以不能把所有情况都说成精确20 ms。

不规则调用会让实际确认时间不确定。
需要严格按毫秒消抖时，应改用时间戳测量连续稳定时长。
本例不使用阻塞延时，主循环可以继续处理其他任务。

## 7. 验证与移植注意

main 用带抖动的按下、松开序列确认恰好产生各一次事件，
还检查 required=1、非法电平和required=0。
每个按键各自持有一个 Button，不能多个按键共用同一状态。
