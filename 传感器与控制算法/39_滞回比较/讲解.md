# 39 滞回比较

配套代码：[滞回比较.c](滞回比较.c)。本例采用标准 C99，无第三方依赖。

## 1. 单阈值为什么容易反复切换

假设温度大于30就开风扇，小于30就关。
读数29.9、30.1、29.9、30.1，会让开关反复动作。

滞回比较使用两个阈值：升到31再开，降到28再关。
28到31之间保持原状态，因此必须保存历史开关状态。

## 2. 参数含义

on 为0表示关、1表示开；input 是当前测量；low 是下阈值；high 是上阈值。
input、low、high 必须使用相同单位，例如摄氏度。
必须满足 low<high，否则无法形成滞回带。

## 3. 判断顺序

~~~text
input >= high：on=1
input <= low：on=0
其余情况：on保持原值
~~~

代码用 if 和 else if，确保一次只执行一个分支。
位于两个阈值之间时，不写 on，就是“保持”的实现。

hysteresis 返回1表示这次调用有效，并不表示开关被打开。
真正的输出在 on 中；参数非法返回0且不改 on。

## 4. 同一个输入为什么可能有两个结果

输入30时：
如果此前温度升到过31，on已经是1，继续保持1；
如果此前温度低于28，on已经是0，继续保持0。

输出取决于当前输入和历史状态，这正是“滞回”的含义。
开机时若输入恰好在中间带，需要由应用指定初始 on，本例初始为0。

## 5. 手算本例序列

~~~text
输入：29  31  29.5  30.5  31  27
输出： 0   1     1     1   1   0
~~~

共两次状态变化，main 既检查逐点输出，也检查变化次数。

## 6. 应用与限制

适合温控开关、电池电压告警、距离接近检测。
如果想“低电压时报警”，可对本输出取反，或另写低阈值触发的明确逻辑。

滞回带应覆盖通常的阈值附近噪声，但过宽会增加切换滞后。
它不是时间消抖：一个足够大的单次尖峰仍然可以越过阈值。
需要“连续满足一段时间才切换”时，结合第40篇的计数确认思想。

## 7. 验证与成本

测试阈值边界、带内保持、变化次数、非法阈值及NaN。
每次 O(1)，无需历史数组。
