# 中值滤波：去掉孤立的尖峰

对应代码：[median.c](median.c)。

## 1. 为什么有时平均值不好用
假设正常距离读数约为 10～13，中间偶尔冒出一个 100。平均值会被它明显拉高。中值滤波把窗口内数据排序，选择处于中间位置的值，因而不会被单个极端值轻易拉走。

它适合抑制孤立跳点，但不能判断跳点一定是错误。真实的窄脉冲也可能被滤掉，连续多数样本异常时也会失效。

输入输出单位相同，窗口为 5。它是非线性滤波，不能像普通 FIR 一样用固定系数加权和表示。

## 2. 先用数字看结果
收到 10、11、100、12、13 后：
```text
时间顺序：10、11、100、12、13
排序之后：10、11、12、13、100
中间值：12
```

下一次输入 14，最旧的 10 离开：
```text
有效读数：11、100、12、13、14
排序之后：11、12、13、14、100
输出：13
```

启动阶段不足 5 个也允许输出。收到两个数 10、11 时，中间两个数平均为 10.5。这个“偶数个取平均”的策略是本例明确选择的规则，不是所有中值滤波实现都相同。

## 3. 状态变量和初始化
samples 保存最近数据；next 指向下次写入位置；count 记录有效数量。MedianFilter filter = {0} 初始化一次，采样时反复调用 median_update。

size_t 是适合数组长度和下标的无符号整数类型。因此不要写一个会在 0 后继续减 1 的循环，它会绕到很大的正数。

## 4. 为什么一定要复制后再排序
原 samples 数组还承担“谁最旧”的记录职责。如果直接排序它，next 就不再指向真正最旧的采样，下次可能删掉错误的数据。

代码创建局部数组 sorted，把有效元素复制过去。sorted 排序后只用来计算这次结果，不修改原来的历史。这个固定长度数组位于局部存储中，不使用 malloc，也不需要 free。

## 5. 插入排序逐步解释
想象把扑克牌按大小插入已排好的左半边。

取出 key = sorted[i]；只要左边那个数比 key 大，就把它向右挪一个位置。重复，直到前一个数不大于 key，或已经走到开头，再把 key 放进去。

以 10、11、100、12 为例，取 key=12：
```text
100 > 12，把 100 右移
11 <= 12，停止
把 12 放到 11 与 100 之间
结果：10、11、12、100
```

while 中 j > 0 必须在前。&& 是“并且”，短路求值会在 j 为 0 时停止，不再读取 sorted[j-1]，从而避免数组越界。

## 6. 怎样找到中间元素
count/2 是整数除法。5/2 得到 2，下标从 0 起，sorted[2] 正好是第三个数。
如果 count 为 4，中间位置是下标 1 和 2，代码把两者平均。

平均前先把一个操作数转成 double，避免两个很大的 float 相加先溢出。最终再转回 float。

## 7. 验证与使用边界
main 使用已知序列，逐个比较预期输出，覆盖奇数、偶数启动窗口和循环覆盖。Infinity 被拒绝，并检查下一条合法数据得到的结果，验证异常没有破坏状态。

5 点窗口可以抵抗窗口中少量极端值，但不能承诺所有噪声都被去掉。窗口越大，排序成本越高，真实细节也可能损失更多。本插入排序每次最坏 O(N²)，附加存储 O(N)，适合小窗口教学。

不要对所有传感器盲目增加窗口；先看异常是不是孤立尖峰，再决定是否使用中值滤波。

## 8. 编译
```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic median.c -lm -o median
```
Windows 运行 ./median.exe；Linux/macOS 运行 ./median。末尾出现 median: PASS 表示演示检查通过。本代码为独立编写的标准中值滤波教学实现。
