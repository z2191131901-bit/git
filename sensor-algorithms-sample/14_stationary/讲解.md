# 静止检测：用一段数据判断，而不是看一个零

对应代码：[stationary.c](stationary.c)。

## 1. 先理解它要解决的问题

陀螺仪零偏标定和零速约束需要先知道设备是否静止。这里结合整段窗口的角速度、加速度模长和三轴波动，避免单个样本碰巧很小就判静止。

## 2. 输入、输出与约定

输入加速度 m/s²、角速度 rad/s；Stationary 用 {0} 初始化并跨采样保存。函数返回值表示输入处理是否成功，*is_still 才是静止判断结果。两者不能混为一谈。

## 3. 公式先看懂每个量

```text
窗口长度 N=32
每条样本：|gyro| <= 0.03，||accel|-9.80665| <= 0.3
三轴样本方差之和 < 0.01 (m/s²)^2
窗口填满且以上全部满足，才判静止
```

## 4. 按执行顺序读代码

### 第 1 步：循环保存历史

acceleration 保存三轴向量，gyro_norm 保存每次角速度大小。next 在 0～31 之间循环。count 未到32前，一律输出非静止，表示证据不足。

### 第 2 步：整个窗口判断门限

检查每条角速度和模长，防止某一时刻的转动被平均掉。正负角速度平均为零，不代表没转动，所以使用模长。

### 第 3 步：计算三轴方差

Welford 算法先求当前样本与旧均值的差 delta，再更新均值，然后求与新均值的差 after，累加两者点积。这样得到三个轴偏差平方和的总量。

### 第 4 步：从累加量变成样本方差

m2/(N-1) 是三轴样本方差之和。它不仅观察加速度大小，也能发现方向抖动；仅对模长求方差会漏掉某些等模方向变化。

### 第 5 步：统一返回

先算副本 next，成功后再写 state 和 is_still。NaN 等异常时不推进窗口，不会稀里糊涂覆盖一条正常历史。

## 5. 代入数字算一次

100Hz 采样、窗口32意味着需要约0.32秒数据。连续32条 [0,0,9.80665] 与零角速度，方差为0，判静止。若新来一条0.2rad/s转动数据，立刻退出静止；它离开窗口后才可能重新进入。

## 6. 参数怎样选

0.03rad/s、0.3m/s²、0.01(m/s²)² 是教学门限，不是所有IMU通用参数。应根据静止噪声、振动环境、安装方式和期望响应时间设置。窗口越长，确认越稳，但恢复判断越慢。

## 7. 常见错误与适用边界

匀速直线运动与静止可能给出一样的 IMU 数据，因此本算法不能保证世界速度为零。若用于车辆零速约束，应结合轮速等外部信息。慢转动可能低于阈值，测量误差也可能误触发。

## 8. 示例验证了什么

验证启动等待、静止确认、转动退出、窗口恢复、零比力拒绝为静止、NaN不修改下标，以及模长接近g但横向振动的情况。每次更新 O(N)，状态 O(N)，这里 N 固定为32。

main 中先调用算法，再用 assert 检查已知结果。assert 条件为假时程序停止；验证时不要定义 NDEBUG，否则会关闭这些检查。函数返回成功只说明完成了本次计算，不代表输入一定符合真实物理条件。

## 9. 编译与运行

在本目录执行：

```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic stationary.c -lm -o stationary
```

Windows 运行 ./stationary.exe；Linux/macOS 运行 ./stationary。当前验证平台为 Windows GCC，未做硬件在环验证。

部分示例使用相对路径包含公共头文件，请保留目录结构。它们不依赖第三方库。也可在上级目录运行 verify.ps1，一次编译并执行全部独立示例。
