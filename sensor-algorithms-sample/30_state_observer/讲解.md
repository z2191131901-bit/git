# 状态观测器：只测位置，怎样估计速度

对应代码：[state_observer.c](state_observer.c)。

## 1. 它不是又一个控制器

控制器计算输入，观测器估计内部状态。LQR需要位置和速度，但可能只能直接测到位置。这里用已知动力学和位置观测，逐步估计速度。

它不等同于简单位置差分，也不保证任何看不见的状态都能估计；需要模型与观测具有合适的可观测性。

## 2. 本篇模型和时刻约定

```text
p[k+1]=p[k]+dt*v[k]+0.5*dt²*u[k]
v[k+1]=v[k]+dt*u[k]
y[k]=p[k]
```

p单位m，v单位m/s，u为实际加速度m/s²。本例采用与LQR篇一致的双积分模型。

observer_update输入当前y[k]和接下来这一周期的u[k]，输出对k+1时刻的估计。不能把下一时刻测量y[k+1]错放到当前残差中。

## 3. 模型预测加残差校正

```text
residual = measured_position-estimated_position
p_hat_next=p_hat+dt*v_hat+0.5*dt²*u+L1*residual
v_hat_next=v_hat+dt*u+L2*residual
```

如果预测位置比测量小，正残差会同时修正位置和速度。这个修正方向来自模型与观测增益设计，而不是说位置偏小就永远应增加速度。

position/velocity存在同一个ObserverState里，先计算next，再整体写回，避免把新位置混进旧时刻计算。

## 4. L1和L2怎么得到

矩阵为：

```text
A=[[1,dt],[0,1]]
C=[1,0]
L=[L1,L2]^T
```

若模型准确、测量无噪声，估计误差满足e_next=(A-LC)e。这里：

```text
A-LC = [[1-L1,dt],[-L2,1]]
```

希望两个离散极点为r1、r2，就匹配特征多项式的迹和行列式：

```text
L1=2-r1-r2
L2=(1-r1)*(1-r2)/dt
```

本篇提供这个专用模型的解析设计，不是通用任意矩阵的极点配置库。

## 5. 手算一轮

dt=0.02，r1=0.8，r2=0.85：

```text
L1=0.35
L2=0.2*0.15/0.02=1.5
```

假设估计p=0、v=0，测量p=1、输入u=0，残差1：

```text
p_hat_next=0.35m
v_hat_next=1.5m/s
```

第一次速度估计可能很大，这是观测器在解释位置估计差异。随着多次校正，误差逐步衰减。不能将初始化阶段估计当成已经准确的真实速度。

## 6. 代码中的极点与周期

observer_design验证dt>0，两个极点位于(0,1)。越接近0通常名义收敛越快，但也可能放大测量噪声；越接近1越慢。

改变采样周期时要重新设计增益。这里极点是离散的，不应把连续系统的负实数极点直接作为pole1/pole2传入。

## 7. 缺测怎样处理

valid=0时残差取0，只按模型预测，measured_position允许传NaN。valid=1却传NaN则返回失败，不修改状态。

缺测期间仍假设输入u已知且模型成立。若输入也不准确，估计误差会增长，不能靠观测器凭空恢复丢失的信息。

cfg必须来自成功的observer_design，不能用未初始化配置调用更新。

## 8. 示例验证

用错误初值估计一段有变化加速度的真实轨迹，检查位置和速度收敛。独立核对A-LC的迹和行列式确实对应0.8、0.85。

另检查缺测预测：p=1、v=2、u=3、dt=0.02时，p_next=1.0406、v_next=2.06；以及无效测量不改状态。

更新O(1)，存储O(1)。这里没有噪声协方差与在线增益优化，和卡尔曼滤波的设计目标不同。

## 9. 编译与参考

```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic state_observer.c -lm -o state_observer
```

运行 ./state_observer.exe。极点配置扩展阅读：[Python Control的place文档](https://python-control.readthedocs.io/en/latest/generated/control.place.html)。本代码独立用解析公式实现固定二维模型。
