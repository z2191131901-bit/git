# 模型前馈：先算大概需要多少，再用反馈修正

对应代码：[feedforward.c](feedforward.c)。

## 1. 前馈与反馈各看什么

反馈看目标与实际值的差距；前馈利用目标和对象模型，提前估算需要的输入。

例如维持一定速度本来就需要克服阻力。只用P反馈时，必须留下一点速度误差才能产生维持输入；如果模型知道所需输入，可以先直接给出，再让反馈处理剩余偏差。

本篇刻意用P反馈、不加积分，便于看清前馈作用。PI在某些条件下也能消除稳态偏差，但它的机制是累积误差。

## 2. 从对象模型推导

假设：

```text
y_dot = -a*y+b*u
```

如果希望y等于reference，y_dot等于reference_dot，代入可得：

```text
u_ff = (reference_dot+a*reference)/b
u = u_ff + Kp*(reference-y)
```

这是模型逆计算，需要b不为0。它不是任何电机都通用的前馈公式；换模型就需要重新推导。

## 3. 示例中的参数与目标

a=2、b=2，因此对象时间常数0.5秒，静态增益b/a=1。输出限制[-1,1]。

目标在前5秒以0.1单位/秒从0升到0.5，随后保持0.5。斜坡阶段reference_dot=0.1，保持阶段为0。

这里的reference_dot来自已知目标轨迹，不是对带噪声测量做差分。目标如果是理想阶跃，导数会含冲激，不能直接照搬这个平滑轨迹示例。

## 4. 代码怎么分工

simulate(enabled,...)执行一遍相同对象仿真。enabled=0时前馈为0，enabled=1时使用模型前馈。

两次仿真采用相同P参数、初值、采样周期、目标和执行器范围，便于比较。每次调用pid_update时把feedforward作为显式输入，和反馈一起限幅，而不是事后偷偷叠加突破范围。

total累加abs(reference-y)*dt，得到一段时间内的绝对跟踪误差积分。它既考虑误差大小，也考虑持续多久。

## 5. 手算某个时刻

t=2秒时，reference=0.2，reference_dot=0.1：

```text
u_ff=(0.1+2*0.2)/2=0.25
```

若当前y=0.18，Kp=1，反馈补充0.02，所以总输入0.27。

进入保持阶段，reference=0.5、导数0，前馈为0.5。模型准确时，u=0.5恰好维持y=0.5，不需要通过持续误差来“挤出”这个维持输入。

## 6. 为什么仅P最后停在0.25

没有前馈时，稳态满足：

```text
0=-2*y+2*(0.5-y)
得到 y=0.25
```

加前馈0.5后，稳态变成：

```text
0=-2*y+2*(0.5+0.5-y)
得到 y=0.5
```

这不是说P一定差或前馈一定准确，而是展示在已知模型下补足维持输入的效果。

## 7. 使用边界

模型参数不准、负载变化或执行器饱和时，前馈也会算错，因此通常保留反馈。实际系统可以使用前馈+PI/PID，但要一起考虑总输出饱和。

不要对目标阶跃直接数值微分并生成巨大前馈，可以先设计速度/加速度受限轨迹。输出已经饱和时，再好的前馈也无法制造额外执行能力。

## 8. 验证与编译

测试比较同一斜坡目标下P与前馈+P的最终值和绝对误差积分。当前模拟P最终0.25，前馈+P最终0.5；这个优势建立在仿真模型与前馈模型匹配的条件下。

```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic feedforward.c -lm -o feedforward
```

运行 ./feedforward.exe。单步控制与模型更新均O(1)。前馈叠加后的饱和讨论参考：[MathWorks](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)。
