# 梯形速度规划：先生成参考运动，再交给控制器

对应代码：[trapezoid.c](trapezoid.c)。

## 1. 为什么目标不能总是突然跳变

位置目标从0瞬间跳到2m，控制器可能立即要求很大速度和驱动力。轨迹规划先把这次移动安排成加速、匀速、减速，再把每个时刻的目标位置、速度和加速度交给控制器。

规划器本身不测量实际位置，也不直接保证电机跟得上。它负责“想怎么走”，控制器负责“根据实际误差尽量做到”。

## 2. 本篇限定条件

起点速度和终点速度都为0。输入start/goal单位m，vmax单位m/s，amax单位m/s²；输出同一时刻的position/velocity/acceleration。

不支持移动中任意初速度接续，不含S曲线的加加速度约束。轨迹起点、终点和分段交界处，加速度可以发生跳变。

## 3. 梯形和三角形怎么判断

匀加速达到vmax需要ta=vmax/amax，单段路程为vmax²/(2amax)。加速和减速两段共需：

```text
ramps_distance = vmax²/amax
```

总距离够大，就有匀速段。距离较短时还没到vmax就必须减速，速度曲线变成三角形：

```text
peak_velocity = min(vmax,sqrt(distance*amax))
ta = peak_velocity/amax
tc = (distance-peak_velocity*ta)/peak_velocity
total_time = 2*ta+tc
```

零距离单独自然退化为总时间0，采样直接返回目标和零速度。

## 4. 结构体为什么分两份

Trapezoid保存一次规划的参数和分段时间，MotionReference保存某一时刻采样得到的参考值。

trajectory_plan只在开始一段新运动时调用。trajectory_sample传入从启动累计的t，不是每次都传固定dt。把t永远传0.01，只会反复得到同一个初始参考点。

direction记录运动方向。先按正距离算路程与速度，再统一乘+1或-1，这样反向运动也使用同一套公式。

## 5. 按三段读代码

加速段：

```text
s=0.5*amax*t²
v=amax*t
a=amax
```

匀速段先加上已经完成的加速路程，再加peak_velocity*(t-ta)。

减速段从终点反算：

```text
remaining=total_time-t
s=distance-0.5*amax*remaining²
v=amax*remaining
a=-amax
```

从终点反算能让末端自然落到目标，不必反复累积位置。t超过总时间后保持目标，速度与加速度归零。

## 6. 手算2米运动

start=0、goal=2、vmax=1、amax=1：

```text
ta=1s，加减速共走1m
匀速剩余1m，所以tc=1s
总时间3s
```

t=0.5s时，位置0.125m、速度0.5m/s。
t=2.5s时，还剩0.5s减速，位置2-0.5*0.5²=1.875m，速度0.5m/s。

若只走0.25m，峰值降为0.5m/s，加速0.5秒再减速0.5秒，没有匀速段。

## 7. 怎样接到之前的串级控制

示例把规划输出接入位置P和速度PI：

```text
目标速度 = 计划速度 + 2*(计划位置-实际位置)
前馈命令 = 计划加速度 + 0.5*计划速度
控制命令 = 前馈命令 + 速度PI修正
```

其中0.5来自仿真对象v_dot=u-0.5v的阻尼。不是任何电机都能直接照抄这个前馈。

速度目标限制到±1.5，驱动力限制到±3；规划本身要求速度不超过1、加速度不超过1，额外余量供反馈纠偏。

## 8. 检查与边界

验证了梯形时长与位置、反向三角形、零距离、负时间拒绝和完整闭环跟踪。实际输出最终位置约1.9999990m、速度约0.0000007m/s。

轨迹满足参考限幅不代表实际速度一定满足同样限幅。负载过大、驱动力不够时可能落后，且本例没有按实际跟踪误差重新规划。

规划和任意时刻采样均O(1)，不动态分配内存。

## 9. 编译与参考

```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic trapezoid.c -lm -o trapezoid
```

Windows运行 ./trapezoid.exe。参考：[WPILib梯形轨迹文档](https://docs.wpilib.org/en/stable/docs/software/advanced-controls/controllers/trapezoidal-profiles.html)。本实现只覆盖明确的静止到静止场景。
