# 加速度计倾角：从重力相关方向看横滚和俯仰

对应代码：[accel_tilt.c](accel_tilt.c)。

## 1. 先明确约定，避免符号抄错
本例使用右手机体坐标系：X 向前、Y 向左、Z 向上，水平静止的加速度计读数为 [0,0,+g]。姿态采用 Z-Y-X 欧拉角约定。

加速度计测量的是比力，静止读数并不是“物体正在向上加速”。这里利用静止时的比力方向推算倾角，不能把输入直接理解为世界系重力向量。

输出 roll 为横滚，pitch 为俯仰，单位都是弧度；转成度需要乘 180/π。这里只处理方向，三轴可统一使用 g 或 m/s²，但不能混用单位。

## 2. 为什么可以用加速度计看倾斜
在静止或平动加速度可忽略时，倾斜会改变三个轴上测得的分量。绕 X 轴倾斜时，Y、Z 分量的比例变化，因此可用它们的方向角求横滚。

如果车辆正在加速或刹车，加速度计读数还包含运动造成的比力变化，这时仅靠它无法分清“倾斜”与“平动”。

## 3. 公式和数值
在上述约定下：
```text
roll  = atan2(ay, az)
pitch = atan2(-ax, sqrt(ay²+az²))
```
水平时 [0,0,1]，两个角都为零。
横滚 +30° 时，静止方向为 [0,0.5,0.8660254]：
```text
roll = atan2(0.5,0.8660254) ≈ 0.523599 rad = 30°
pitch = 0
```
俯仰 +30° 时，输入为 [-0.5,0,0.8660254]，所以 -ax 为正，pitch 得到 +30°。

正负号依赖坐标与姿态定义。接实际传感器前，应先统一安装轴向，再用已知倾斜方向核对，不能看到结果反了就随意删负号。

## 4. 为什么用 atan2 而不是 atan
atan(ay/az) 会先除法，当 az 为零时会遇到问题；而且比值会丢失两个参数原本的象限信息。

atan2(y,x) 同时考虑 y 与 x 的符号，能区分方向。参数顺序不能交换，atan2(ay,az) 与 atan2(az,ay) 一般不是同一个角。

## 5. 代码逐步对应
Tilt 结构体把 roll 和 pitch 放在一起，通过 Tilt *output 返回两项结果。

hypot(ay,az) 计算 sqrt(ay²+az²)，得到向量在 YZ 平面的投影长度；相比直接用 float 平方相加，它对极大或极小量更稳健。代码用 double 做中间计算，再转为 float。

length 为三维向量长度。零向量没有方向，直接拒绝。yz_length/length 过小时，方向接近 X 轴，这时横滚角不可可靠确定，函数也返回失败。

最后先算 next，再执行 *output=next。因此失败时调用者原有角度不会被覆盖。

## 6. 为什么不输出偏航角
仅绕竖直方向转动，静止加速度计感受到的方向不随之提供航向信息。不能把“没有算出航向”写成“航向确定为 0”。本例干脆不提供 yaw 成员。

pitch 采用 [-90°,90°] 主值，接近 ±90° 会遇到欧拉角奇异性。即使四元数内部没有这种参数奇异性，转换成欧拉角显示时仍会遇到。

## 7. 验证与硬件使用
main 检查水平、横滚 30°、俯仰 30°、零向量、X 轴奇异方向和 NaN。

函数返回成功只说明数值能计算，不代表设备真的静止。可以结合模长是否接近 g、角速度和一段数据的方差判断可信度；但单看模长接近 g 也不能完全排除运动加速度。

时间 O(1)，额外存储 O(1)。本例没有低通处理，实际使用可先对各轴适当滤波，但滤波延迟也会影响结果。

## 8. 编译与参考
```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic accel_tilt.c -lm -o accel_tilt
```
Windows 运行 ./accel_tilt.exe，Linux/macOS 运行 ./accel_tilt。
