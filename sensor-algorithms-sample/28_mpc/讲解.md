# MPC：先预测几步，算出计划，只执行第一步

对应代码：[mpc.c](mpc.c)。

## 1. MPC到底多了什么

PID根据当前与过去的误差计算控制。MPC使用模型预测不同控制计划的未来结果，选择代价较小且满足约束的计划。

最关键的循环是：

```text
测量当前状态 -> 预测与优化 -> 只执行计划第一步
下一次重新测量 -> 重新预测与优化 -> 再执行第一步
```

后续预测可能因扰动和模型误差失准，所以不是一次算好两步就闭眼全执行。

## 2. 为了看懂，本篇把问题缩到多小

状态只有一个x，未来控制有两个连续变量u0、u1。模型为：

```text
x_next = 0.9*x + 0.2*u
```

x/u采用归一化单位，模型系数对应一个固定采样周期。代码每循环一次就是一个模型周期，若改变真实采样周期，需要重新辨识或离散化A/B，不能只让循环跑快一点。

约束为：

```text
0 <= u0,u1 <= 1
0 <= x1,x2 <= 1.2
```

这是连续控制量的两步线性MPC，不是离散开关的有限控制集MPC，也没有使用控制网格作为真正求解器。

## 3. 把两步预测展开

第一步：

```text
x1=A*x+B*u0
```

将它代入第二步：

```text
x2=A*x1+B*u1
  =A²*x+A*B*u0+B*u1
```

因此计划U=[u0,u1]^T与预测状态之间是线性关系：

```text
[x1] = [A*x ] + [ B   0] [u0]
[x2]   [A²*x]   [A*B  B] [u1]
```

make_constraints和构造代价函数都用这同一套预测关系。

## 4. 好计划如何打分

本例代价：

```text
J = (x1-reference)² + (x2-reference)²
    + R*((u0-u_equilibrium)²+(u1-u_equilibrium)²)
R=0.02
u_equilibrium=(1-A)*reference/B
```

前两项希望未来状态接近目标，后两项不希望控制偏离维持目标所需的平衡输入太多。

为什么不是直接惩罚u²？因为本模型在非零目标上本来就需要非零维持输入。例如reference=0.8时，u_equilibrium=0.4。盲目把u压向0可能产生静态跟踪偏差。

这种平衡输入处理依赖模型准确，不等于实现了对未知恒定扰动的无偏MPC；后者还需要扰动模型、状态扩展等设计。

## 5. 输入与状态约束怎样变成代码

统一写成：

```text
c0*u0+c1*u1 <= bound
```

例如u0>=0写为-u0<=0；x1<=1.2写为B*u0<=1.2-A*x。

8条约束分别来自u0/u1上下限与x1/x2上下限。Constraint结构体保存一条不等式的两个系数和右侧常数。

本例约束的是未来x1/x2。当前实测x即使暂时超过1.2，只要能在下一步恢复并满足预测约束，仍允许求解。这与先强制拒绝所有初始越界状态不同，使用时要看清策略。

## 6. 二次型H和g来自哪里

将代价展开：

```text
J = 0.5*U^T*H*U + g^T*U + 与U无关的常数
G = [[B,0],[A*B,B]]
d = [A*x-reference, A²*x-reference]
H = 2*(G^T*G+R*I)
g = 2*(G^T*d-R*[u_equilibrium,u_equilibrium])
```

本例H为：

```text
[0.1848  0.0720]
[0.0720  0.1200]
```

R为正使代价严格凸，存在可行解时最优计划唯一。H固定，因此这种小模型不需要调用通用矩阵库。

注意LQR/MPC的Q/R是代价权重，不是卡尔曼的噪声方差。

## 7. 求解器为什么只需检查三类点

两个变量的线性约束构成平面上的可行多边形。严格凸二次函数的最小值可能在内部、一条边上或顶点。

**内部候选：** 无约束极小值U_free=-H逆*g。若满足全部约束，它就是最优解。

**边界候选：** 暂时把某条不等式当成等式，求这条直线上的极小值：

```text
v = H逆*c
lambda=(c^T*U_free-bound)/(c^T*v)
U=U_free-v*lambda
```

**顶点候选：** 求两条非平行约束边界的交点；平行时跳过，避免除零。

consider统一检查候选是否满足全部约束，并计算原始代价。只保存可行候选中代价最小者。8条约束最多检查1+8+28=37个候选。

这利用了问题仅有两个变量的特殊性；维度增加后，不应照搬暴力枚举所有活跃约束组合。实际较大MPC通常使用专门QP求解器。

## 8. 手算三个工况

**已经到目标：** x=reference=0.8。选择u0=u1=0.4，则x1=x2=0.8，状态误差与控制偏离都为0，总代价0。

**从0追到0.8：** 最优计划此时触及输入上限u0=u1=1：

```text
x1=0.2
x2=0.9*0.2+0.2=0.38
J=(0.2-0.8)²+(0.38-0.8)²+0.02*(0.6²+0.6²)
 =0.5508
```

不是直接把无约束解逐项截断，而是枚举并比较全部可行候选后得到该方案。其它工况下，简单截断通常不等于约束最优解。

**状态上界生效：** 当前x=1.3，目标1.2。x1=1.17+0.2*u0<=1.2，因此u0<=0.15。最优计划u0=0.15、u1=0.6，x1=x2=1.2，代价0.00405。

## 9. 无可行解时怎么办

如果x=1.5，即使取最小输入u0=0，第一步也为1.35，超过1.2。没有任何计划能同时满足现有模型与硬约束。

函数返回0且保留原输出。调用者不能因此把旧计划当成新解直接执行；应进入应用明确设计的失败处理流程。本教学仿真用assert停止，不擅自替真实设备决定安全动作。

工业设计可能采用软约束、松弛变量和经过验证的备用控制。本篇都未实现，不能把失败返回当成完整故障处理。

## 10. 示例怎样验证

除上述可手算工况外，示例还做：

- 连续求解100次，每次只执行u0，最后接近0.8。
- 检查执行输入与下一状态不越界。
- 对几种工况遍历101×101的可行控制网格，确认解析求解的代价不比任何网格方案更差。

网格只是独立检查，不参与正式控制求解。模型预测约束也只对模型成立；真实系统有误差和扰动时，需要裕量或鲁棒设计。

## 11. 参数与稳定性边界

预测更长可能看得更远，但计算量和模型误差影响也会改变。R越大通常越不愿偏离平衡输入。

本例没有终端集合、终端稳定性条件、输入变化率约束、扰动估计或通用QP接口。闭环仿真收敛只验证给定案例，不构成任意初值与参数下的稳定性证明。

MPC不是把PID里的三个系数换成几个新系数，模型、采样周期、参考轨迹、约束可行性与求解时间都属于设计的一部分。

## 12. 编译和参考

```sh
gcc -std=c99 -Wall -Wextra -Werror -pedantic mpc.c -lm -o mpc
```

运行 ./mpc.exe。固定二维、8条约束时成本有固定上界；一般约束数m时本枚举方式最多O(m³)，因为每个O(m²)候选还检查m条约束。

扩展阅读：[OSQP MPC示例](https://osqp.org/docs/examples/mpc.html)。本代码独立实现二维求解，不调用OSQP，也不代表具备它的通用求解能力。
