# 37 编码器＋IMU＋航向＋位置：五状态平面 EKF

配套代码：[navigation_ekf.c](navigation_ekf.c)。
先读 [第35篇](../35_encoder_gyro/讲解.md)，再把本篇理解为“预测之后，接收新传感器的纠正”。

## 1. 本例具体融合了什么

| 数据 | 在本例中的角色 | 输入单位 |
| --- | --- | --- |
| 陀螺仪 Z 轴角速度 | 预测航向 | rad/s |
| 去重力、已校准的前向加速度 | 预测前向速度 | m/s² |
| 编码器前向速度 | 修正速度 | m/s |
| 经校准和坐标对齐的磁航向 | 修正航向及相关状态 | rad |
| GNSS/UWB等定位模块输出的局部位置 | 修正 x、y 及相关状态 | m |

程序融合的是传感器经过处理后的观测，没有串口、CAN、SPI 驱动。
GNSS 经纬度转换、UWB 测距定位、磁场校准不在本文件里。
外部位置也可以来自已完成坐标对齐的视觉/激光定位，但要注意观测之间的相关性。

这是水平、无侧滑车辆的平面 EKF。
它没有三维姿态和加速度计零偏状态，不等于把第36篇接上了完整三维组合导航滤波器。

## 2. 为什么只选五个状态

~~~text
s = [x, y, yaw, v, bg]^T
~~~

x、y 是世界平面位置；yaw 是航向；v 是有符号前向速度；bg 是 Z 轴陀螺仪零偏。

这里 v 是机体前向速度，世界速度由 v*cos(yaw)、v*sin(yaw) 得到。
这隐含了车没有侧滑。不能把这个状态定义原封不动用于横向移动的全向底盘。

加入 bg 的原因：第35篇已经展示固定陀螺仪零偏会变成明显位置漂移。
本例让外部航向和运动观测通过协方差关系帮助估计 bg。

## 3. P 矩阵到底存什么

P 是 5×5 的估计误差协方差矩阵。
对角线表示每个状态的不确定程度，非对角项表示不同状态误差之间的关联。

~~~text
P[x][x] 的单位是 m²
P[yaw][yaw] 的单位是 rad²
P[v][v] 的单位是 (m/s)²
P[bg][bg] 的单位是 (rad/s)²
P[x][yaw] 的单位是 m·rad
~~~

初始化方差为 [1,1,0.25,0.25,0.01]，对应标准差 [1 m,1 m,0.5 rad,0.5 m/s,0.1 rad/s]。
这是示例初值，实际应根据你对初始状态的把握设置。
main 已知小车最初速度为 1 m/s，所以单独把初始 v 改为 1。

不可以把“标准差 0.1 m”直接填成 R=0.1；方差应为 0.01 m²。

## 4. 预测方程逐行对照

~~~text
x_next   = x + v*cos(yaw)*dt
y_next   = y + v*sin(yaw)*dt
yaw_next = wrap(yaw + (gyro_z-bg)*dt)
v_next   = v + forward_accel*dt
bg_next  = bg
~~~

为便于看清雅可比，使用一阶欧拉递推，位置使用旧速度和旧航向。
第35篇用恒定转速圆弧公式，本篇没有复制它；两种数值积分的精度不完全相同。
程序限制 0<dt≤0.1 s，仿真使用 0.01 s；这个限制不代表 0.1 s 在所有动态下都够用。

forward_accel 必须是沿车体前向的运动加速度。
水平模型下可以使用已校准的机体 X 加速度；上坡时重力会投影到 X 轴，不能继续直接使用原始读数。
处理坡道需要姿态估计、重力补偿和相应运动模型。

## 5. 雅可比 F 是怎么来的

F 的每个元素是“新状态对旧状态的偏导数”。
例如 x_next=x+v*cos(yaw)*dt：

~~~text
对 x 求导：1
对 yaw 求导：-v*sin(yaw)*dt
对 v 求导：cos(yaw)*dt
~~~

因此，按 [x,y,yaw,v,bg] 顺序：

~~~text
F = [1  0  -v*sin(yaw)*dt  cos(yaw)*dt  0
     0  1   v*cos(yaw)*dt  sin(yaw)*dt  0
     0  0   1              0           -dt
     0  0   0              1            0
     0  0   0              0            1]
~~~

P_pred=F*P*F^T+Q。
代码先算 product=F*P，再算 product*F^T，用三个循环实现普通矩阵乘法。
最后一个矩阵访问 transition[j][k]，正是转置位置，写成 transition[k][j] 就错了。

Q 用对角“每秒协方差增长率×dt”的教学近似：
x/y 为 0.0025 m²/s，yaw 为 0.0004 rad²/s，
v 为 0.04 (m/s)²/s，bg 为 0.000001 (rad/s)²/s。

这不是从完整连续随机模型严格积分得到的 Q。
真实系统应按输入噪声、零偏随机游走和离散时间模型确定 Q，必要时包含交叉项。

## 6. 一个 observe 函数为什么能接多个传感器

本例每次测量一个状态分量，index 指定测的是哪个：

~~~c
observe(&filter, SPEED, wheel_speed, speed_variance, 9);
observe(&filter, YAW, heading, heading_variance, 9);
observe(&filter, PX, position_x, position_variance_x, 9);
observe(&filter, PY, position_y, position_variance_y, 9);
~~~

对应观测矩阵 H 只有 index 那一项是 1，其余为 0。
所以不用写一个通用矩阵求逆，只要计算标量：

~~~text
residual = measurement - state[index]
S = P[index][index] + R
K[i] = P[i][index] / S
state_new[i] = state[i] + K[i]*residual
~~~

注意 K 有五个分量。测到航向时，不只是 yaw 会变；
只要 P[bg][yaw] 非零，bg 也会得到修正。

预测中的 F[yaw][bg]=-dt 会逐渐建立航向与零偏的相关性。
这就是外部航向能帮助估计陀螺仪零偏的代码路径。

## 7. 手算一次位置修正

设预测位置 x=0，位置方差 Pxx=1；测到 x=2，测量方差 R=1。

~~~text
residual = 2 - 0 = 2
S = 1 + 1 = 2
Kx = 1/2
new_x = 0 + (1/2)*2 = 1
new_Pxx = 0.5
~~~

预测和测量具有相同不确定度，因此结果落在中间。
main 单独测试了这个已知结果，避免只看轨迹像不像。

R 越小代表越相信测量，不代表传感器真的变准了。
若输入质量差还把 R 填得很小，滤波器会过度相信错误观测。

## 8. 航向跨越 ±π 怎么办

预测 179°，测量 -179°，普通相减得到 -358°，实际上只需要修正 +2°。
因此航向残差先经过 wrap，修正后的航向也再次 wrap。
main 专门检查了这个边界。

磁力计输入应先完成硬铁/软铁校准、倾斜补偿及世界系方向对齐。
若世界 X 定义为东，而磁航向零度定义为北，必须转换。
参考 [磁场校准](../16_mag_calibration/讲解.md) 和 [磁航向](../17_magnetic_heading/讲解.md)。
地区磁偏角也需要处理，不能把磁北直接当真北。

## 9. 异常值如何拒绝

代码计算：

~~~text
abs(residual) / sqrt(S) > sqrt(gate2)
~~~

gate2=9 对应标量创新的 3σ 门限。
超过就返回 0，整个状态和协方差都不修改。
参数非法返回 -1，正常接受返回 1，调用方要区分这三个结果。

main 给磁航向加入约 2 rad 异常，又给 x/y 同时加入 100 m 跳变，检查三次标量拒绝。
这不是故障诊断系统：缓慢偏移、小幅持续磁干扰可能通过门控。
初始状态严重错误时，正常观测也可能被拒绝，应先初始化或设计重定位逻辑。

## 10. 为什么用 Joseph 协方差更新

~~~text
A = I - K*H
P_new = A*P*A^T + K*R*K^T
~~~

程序显式展开这两个矩阵乘法，然后对称化，以减少浮点误差积累。
协方差不能只更新对角线，否则状态之间的关联会丢失。

valid 只检查有限性、对角线和对称性；这些条件不足以保证半正定。
初始化要提供合法协方差。仿真额外使用 Cholesky 分解逐步检查完整 P 为正定，
避免把“对角线都大于零”误当作充分检查。

## 11. 不同频率如何安排

仿真每 0.01 s 预测一次，相当于 IMU 100 Hz；
每两步轮速更新一次，即 50 Hz；
每十步航向更新一次，即 10 Hz；
每二十步位置更新一次，即 5 Hz。

没有某个传感器的新数据，就跳过它的 observe。
不能重复融合上一帧，也不能把缺失值填成零位置。

本例观测都对应当前预测时刻，没有传输延迟。
真实串口、网络或视觉数据应按测量时间戳对齐。
迟到数据需要历史状态回放等处理，本例没有实现，不能仅在到达时刻直接当当前观测。

## 12. 外部位置中断仿真

真值是速度 1 m/s、角速度 0.08 rad/s 的解析圆周运动。
陀螺仪含 0.02 rad/s 固定零偏和小幅确定性扰动。

dead 分支只有相同的 IMU 预测与轮速更新；
fused 分支另外接收航向和位置。两者使用相同初始状态。
因此这里比较的是整个外部辅助的效果，不能把改善全部归功于某一种传感器。

10~18 秒关闭位置更新，但轮速与航向仍然存在。
这不是所有传感器都断开的测试。
输出同时记录中断结束、恢复一段时间后、最终的位置误差。

实际仿真输出见 [验证记录](../惯导融合验证.md)。
它使用固定正弦扰动，没有随机蒙特卡洛统计，不代表实车可达到厘米精度。

## 13. 接 GNSS、UWB、视觉/激光时的区别

GNSS 经纬度必须先转换到一致的局部米制坐标系，不能直接把经度作为 PX 输入。
UWB 原始测距满足“到基站的距离”模型，不是位置观测；
需要先解算位置，或者另外实现距离观测函数及雅可比。

同一定位模块的 x、y 若存在测量相关性，应使用完整二维 R 和联合更新。
本例顺序标量更新要求 x/y 测量噪声互不相关；即使满足该条件，逐轴门控也不等于二维联合门控，
可能只接受某一轴，整包原子拒绝需另行设计。

视觉/激光里程计的局部坐标可能需要旋转和平移对齐。
若定位模块内部已经融合了同一个 IMU，再与原始 IMU 当成独立信息融合，可能重复计入信息。
同样不要把同一编码器的速度和积分位置都当作独立观测输入。

天线、UWB标签、IMU、轮轴中心往往不在同一点。
本例假设它们对应同一参考点；实际旋转时应处理杆臂，否则位置观测会随转向出现偏差。
